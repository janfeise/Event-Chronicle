## 三、根因分析

### 根因 1（致命）：角色名在 `parseTestMessages` → `formatMessages` 链路中丢失

```
测试输入原始格式:
  [小明]: 周末有什么安排吗？
  [小红]: 没有，在家闲着。

        │ parseTestMessages()
        │ roleMap["小明"] ?? "user" → role: "user"
        ▼

formatMessages() 输出:
  user:
  周末有什么安排吗？

  user:
  没有，在家闲着。

        │ LLM 接收到的内容中
        │ 所有说话者都变成了 "user"
        ▼

LLM 无法区分不同说话者，
只能使用 "用户A/用户B" 或 "user" 等泛化称谓。
```

**影响面**: 覆盖全部 37 个用例的 `participants` 字段，是本次测试中覆盖面最广、影响最严重的单一问题。

**修复方向**（供参考，本次不修改代码）:

1. `ChatMessage.role` 从 `"system" | "user" | "assistant"` 放宽为 `string`，容纳任意角色名
2. 或 `formatMessages` 改为输出 `[角色名]: 内容` 格式，保留原始身份
3. 或测试解析器将 `[小明]:` 保留在 content 中，不通过 role 字段传递

### 根因 2：Prompt 中参与者命名约束不足

当前 `extract-event.md` 提到参与者字段，但未明确要求 **从聊天记录照抄角色名**。LLM 在角色名被泛化后，倾向于使用占位名。

应增强的 Prompt 规则:
> participants 必须使用聊天记录中 `[角色名]:` 前缀的**原始名称**，不得使用 "user"、"用户"、"用户A" 等泛化称谓。

### 根因 3：事件压缩倾向性偏差（过压缩）

| 用例 | 预期 events | 实际 events | 偏差 |
|---|---|---|---|
| TC-1.4 项目进展 | 3 | 1 | -67% |
| TC-3.1 顺序时间线 | 3 | 1 | -67% |
| TC-5.3 遗迹探索 | 3 | 2 | -33% |
| TC-7.5 调查任务 | 2 | 1 | -50% |

LLM 倾向于**过度合并**，将多个顺序状态变化合为一个。Prompt 中虽有「不应过度压缩」的规则，但在实际推理中权重不够。

应增强的方向: 增加**对比示例（contrastive examples）**，明确展示:
- ✅ 应该分开记录的情况（进入 → 离开，两个独立状态变化）
- ✅ 可以合并的情况（洗菜 → 切肉 → 炒菜，同类连续动作）
