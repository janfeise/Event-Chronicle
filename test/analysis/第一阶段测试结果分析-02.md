## 五、根因分析

### 根因 1：Prompt 压缩倾向仍然过强

TC-3.1、TC-5.3、TC-10.1 均表现为 **过度合并**：

```
TC-3.1: 找书+地图 → 决定前往 → 离开 (3) → LLM 输出 1 个
TC-5.3: 击败+进入 → 拿宝石 → 坍塌逃脱 (3) → LLM 输出 1 个
TC-10.1: 解读碑文 → 决定出发 → 伤势恢复 → 制作路线图 (4) → LLM 输出 2 个
```

当前 Prompt 中的 Timeline Principle 说「目标不是生成最少事件」，但 LLM 在实际推理中仍然倾向于合并。原因是 **缺少「应该分开」的对比示例**。

### 根因 2：低重要性事件的过度过滤

TC-5.4（烹饪过程 → 烹饪完成）和 TC-7.1（早晨例行事务）都返回了空数组。

这两者都属于 **importance 1-3 的日常事务**。LLM 可能将「日常事务」误解为「不应记录」，而非「记录但标注低分」。

Prompt 中虽有重要性分级的说明（1-3 日常事务），但与「Do Not Record」部分之间没有明确界限声明，导致 LLM 将低重要性事件也一并过滤。

### 根因 3：summary 冗长

多数用例的 summary 包含环境描写、对白细节等冗余信息：

| 用例 | 实际 summary | 问题 |
|---|---|---|
| TC-1.2 | "用户推开橡木门，走进了一座古老的图书馆，馆内高耸的书架和昏黄的灯光映入眼帘，空气中弥漫着陈旧纸张的气息。" | 环境描写占 70% |
| TC-1.8 | "队长带领队员A和队员B抵达废弃工厂，下令分散搜索。队员A在二楼发现文件，队员B在地下室发现一辆被遗弃的货车。" | 过程细节过多 |

Prompt 中「Writing Style」说「使用简洁客观的描述」「优先描述结果」，但 LLM 执行不充分。需要在 Output 格式说明中增加 **summary 长度约束**（如「1-2 句话，仅描述状态变化结果」）。

### 根因 4：participants 仍存在细节偏差

角色名修复后大方向正确，但有细节问题：
- TC-1.5: 助手加入 participants（助手仅提问，未直接参与事件）→ 预期仅侦探
- TC-1.6: 同伴加入 participants（同伴仅观察物品，未获得物品）→ 预期仅冒险者  
- TC-2.6: participants 含"团队"（泛化实体）→ 预期成员 A/B/C
- TC-1.1: participants `["User"]` vs 预期 `["用户"]`（英文 vs 中文）→ Prompt 中说的是"使用聊天记录中实际出现的角色名"，但英文 User 未被翻译

## 七、改进优先级建议（仅 Prompt 层面）

| 优先级 | 改进项 | 具体操作 |
|---|---|---|
| **P0** | 增强压缩边界示例 | 在 Event Compression Rules 中增加正例+反例：展示 3 个独立状态变化应分开记录 vs 连续同类动作可合并 |
| **P0** | 明确「日常事务」处理规则 | 在 Do Not Record 之后增加：「日常事务（1-3 分）属于记录范围，只是重要性低。仅当无任何状态变化时才不记录。」 |
| **P1** | summary 长度约束 | 在 Output 格式说明中增加：「summary 仅 1-2 句话，只描述状态变化的最终结果，不包含过程或环境描写。」 |
| **P2** | participants 精确性 | 增加规则：「仅记录状态变化的直接参与者。提问者、旁观者、道具提及者不纳入 participants。」 |
| **P2** | 角色名大小写/语言一致性 | 明确：「角色名使用聊天记录中的原文，User→用户、AI→AI，不做翻译。」 |
